## 일별 예상 매출 제안 형식

키: `date + region + industry + age`, 중복 없이 1행.

| 열 | 의미 |
|---|---|
| date | YYYY-MM-DD |
| region | 카드 표기 `강원 춘천시` |
| industry | 카드 원본 업종명 유지, 임의 문자열 매칭 금지 |
| age | 10대·20대·30대·40대·50대·60대 이상 |
| amount | 실제 매출, 제공 단위 |
| prediction | 예상 매출, 실제 매출과 같은 단위 |
| model_id | 모델·산식 버전 |
| train_start / train_end | 해당 예측의 학습 기간 |
| prediction_status | 계산됨 / 자료 부족 등 명시 |

산식, 입력변수, 기상변수 처리, 재실행 명령, 학습·평가 범위와 예측 목적(사전 예측/사후 기준선)을 함께 전달한다. 실제로 재실행한 뒤 날짜별 키·행 수·결측·값 일치를 확인한다.

## 사건별 결과 결합

공통 키는 `event_id + region + industry + age + window_start + window_end`다. 창은 지표를 비교하는 동일한 사건·관찰 범위이며, 사건 발생 기간은 별도 사건 목록에서 확인한다. 같은 event_id라도 범위가 다르면 결합하지 않는다. 업종 전체 집계는 `age=ALL`, 연령별 상세는 실제 연령 구간을 쓴다. 전체와 연령별을 같은 순위 목록에 섞거나 합산하지 않는다.

| 담당 | 열 | 정의·검토 조건 |
|---|---|---|
| 선하 | decline_rate | 사건 기간 예상 매출 대비 감소율. 기간·분모·부호 명시 |
| 선하 | gross_shortfall | 지정 창에서 max(예상−실제, 0)의 합 |
| 선하 | net_shortfall | 같은 창에서 (예상−실제)의 합. 초과 매출은 차감 |
| 선하 | net_shortfall_rate | 순누적 부족 / 같은 창의 예상 매출 합. 분모 0은 결측 |
| 선하 | sales_uncertainty_note | 예상 매출 방법별 차이·관측 부족 등 |
| 세은 | recovery_days | 사건 종료 후 회복까지 일수. 기준·연속 충족 일수 명시 |
| 세은 | recovery_status | recovered / censored / insufficient_data 등 |
| 세은 | recovery_uncertainty_note | 기준 변경·관찰기간·사건 중첩에 따른 차이 |
| 공동 | decline_only_rank | 같은 대상·기간에서 감소율만으로 매긴 비교 순위 |
| 공동 | support_priority | 공동 산정 기준 확정 후 계산 |
| 공동 | priority_uncertainty_note | 설정에 따라 순위가 바뀌는 정도·추가 확인 필요성 |
| 공동 | review_status | 입력 대기 / 공동 검토 대기 / 검토 완료 등 |

금액의 단위를 확인하기 전 원/백만원으로 임의 환산하지 않는다. 비율은 10%=0.1로 저장한다. 미회복은 임의의 최대 일수나 0으로 바꾸지 않는다. 미수신·결측과 실제 0을 구분한다.

## 회의용 표 구조

| 사건·업종·연령 | 감소율 | 누적 부족(합계/순부족) | 회복 지연 | 불확실성 | 감소율 순위 | 지원 우선순위 |
|---|---|---|---|---|---|---|
| 실제 결과 수신 대기 | 미수신 | 미수신 | 미수신 | 검토 대기 | 미산출 | 미산출 |

가중치나 종합 점수는 아직 정하지 않았다. 지표를 나란히 보여주고, 기간·단위·결측·미회복 처리와 산정 규칙을 공동 확정한 뒤 순위를 만든다. 불확실성은 부족액에 임의로 가산하는 점수가 아니라 결과 해석과 추가 확인 필요성을 함께 보여주는 정보다. 이후 단순 감소율 순위와의 차이를 검토한다(#13).

## 템플릿 생성·검사

```bash
python scripts/prepare_priority.py --output outputs/joeun_1004/priority

python scripts/prepare_priority.py --sales data/processed/event_sales.csv --recovery data/processed/recovery.csv --output outputs/joeun_1004/priority
```

입력이 없을 때는 헤더만 있는 CSV 3개를 만든다. 실제 결과처럼 보이는 예시 수치나 업종 순위를 넣지 않는다. 수신 후에는 중복·결합 키·관찰기간 일치 여부를 검사하며, 결합 성공만으로 순위나 지표의 타당성 검토가 완료되는 것은 아니다.
