# 춘천·강남 여름철 최고기온과 카드 매출 비교

## 연구 질문과 범위
같은 날짜·업종·연령의 관측 매출을 비교할 때 최고기온과 지역·업종별 기온 조합항이 시간 순서 평가 성능을 개선하는가? 춘천의 반응이 더 크다는 것은 검토할 가설이지 전제나 결과가 아니다. 관광지 여부는 실제 변수로 측정하지 않았다.

이번 경로는 실제 관측 기온을 사용한 탐색적 조건부 매출 예측이다. 미래 날씨 예보 모델, 폭염이 없었을 때의 반사실 매출, 인과적 피해액 또는 기존 회복·지원 기준선의 대체가 아니다. 기존에 본 자료를 재분석하므로 완전히 미열람한 최종 평가라고 부르지 않는다.

## 입력·전처리
- 카드 데이터1의 개인 매출: 날짜×지역×업종×연령. 성별·시간대 합산, 법인 제외, 60대 이상 통합. 거래건수는 매출과 동시 결정되므로 설명변수로 사용하지 않는다.
- 춘천 ASOS 101, 강남 AWS 400의 일 최고기온. 서울 ASOS 108을 쓰지 않는다. 출처: 기상청 기상자료개방포털(https://data.kma.go.kr), 각각 ASOS/AWS 일자료 CSV 다운로드. 춘천 수집일 2026-10-01(팀 제공 기록), 강남 수집일 2026-10-26(사용자 제공 파일).
- 강남 CSV는 9/11 행 누락, 9/10 최고기온 결측. 7~8월은 최고기온이 완전하다. 원자료 점검 내역은 실행 메타정보에 저장한다. 습도가 없으므로 체감온도 계산은 하지 않는다.
- 분석 기간은 두 지역 모두 2025-07-01~08-31. 동일 날짜×업종×연령에 두 지역의 매출이 모두 존재하는 쌍만 유지한다. 누락 매출을 0으로 만들지 않는다. 이 완전 관측 표본은 모든 업종을 대표하지 않을 수 있다.
- 매 fold의 학습자료에서 두 지역 모두 7개 이상 관측과 양수 평균이 있는 업종·연령만 평가한다. 두 지역의 평가 키는 같다. 제외 규모와 학습 기온 범위 밖 관측을 별도 기록한다.
- 공휴일 달력은 검증된 팀 calendar.csv의 0/1 값. 키 중복·날짜 누락을 거부한다.
- 일강수량은 이번 주 모델에 포함하지 않는다. 춘천의 공란과 강남의 명시적 0을 같은 실제 값으로 간주하지 않는다. 강수·습도·관광·행사 등 미통제 요인이 남는다.

## 비교 모형
모든 Ridge 모델의 타깃은 매출/해당 지역×업종×연령의 학습 평균이다. 강남의 큰 금액이 학습을 독점하지 않도록 조정하고 예측은 각 학습 평균을 곱해 원 단위로 복원한다. 정규화는 평가자료를 사용하지 않는다.

| 모형 | 설명변수 |
|---|---|
| 요일 평균 | 학습자료의 지역×업종×연령×요일 평균. 해당 요일 미관측 시 같은 셀 학습 평균 |
| M0 | 지역×업종×연령 범주, 지역×요일 범주, 선형 날짜 추세, 공휴일 |
| M1 | M0 + (최고기온−30)/5 + max(최고기온−33,0)/5 |
| M2 | M1 + 지역×기온·초과기온 + 업종×기온·초과기온 |

33℃는 최고기온 반응의 구간을 나누는 고정 절점이며 공식 폭염특보나 기존 추정 체감온도 33℃ 사건과 같지 않다. 선형 추세는 30일 단위, 기온은 5℃ 단위로 고정 스케일링한다. 원핫 인코딩 사전은 각 학습자료에만 fit한다. Ridge LSQR tol=1e-8, 최대 반복 20000. 음수 예측은 0으로 절단한다.

## 시간 순서 검증
| 역할 | 학습 기간 | 평가 기간 |
|---|---|---|
| 설정 선택 | 7/1~7/21 | 7/22~8/4 |
| 평가 1 | 7/1~8/4 | 8/5~8/18 |
| 평가 2 | 7/1~8/18 | 8/19~8/31 |

각 M0~M2의 alpha 후보는 0.1, 1, 10, 100. 첫 구간에서 두 지역 WAPE의 동일 가중 평균으로 선택하고 이후 두 구간에서는 고정한다. 각 평가 시작 전에만 학습기간을 확장하며 평가기간 도중 재학습하지 않는다. 후보 경계에서 선택되어도 추가 탐색하지 않으며 전역 최적이라고 주장하지 않는다. 요일 평균은 같은 학습행과 평가행을 쓴다.

지역별 WAPE·MAE·RMSE와 전체 합산 지표를 보고한다. 전체 합산 WAPE는 큰 매출 지역에 더 영향을 받으므로 지역별 결과를 우선 해석한다. WAPE는 예측오차이지 폭염 피해율이 아니다. 지역별 예측오차 차이만으로 기온 민감도 차이를 입증할 수 없다.

## 기온 반응의 보조 설명
M2에서 다른 변수를 고정하고 최고기온만 +1℃ 변경한 예측 차이를 계산한다. 원 기온과 변경 기온이 각각의 지역 학습 범위 안이고, 두 지역 모두 같은 날짜×업종×연령에서 계산 가능한 경우에만 쌍으로 비교한다. 단위는 학습 셀 평균 매출 대비 예측 차이이며 실제 매출 증감률 또는 인과효과가 아니다. 공통 지지 범위 안이라도 행사·강수·시즌 등 교란을 제거하지 못한다. 시점별 추정과 업종별 변화를 함께 보고, 유의성이나 관광 메커니즘을 주장하지 않는다.

## 실행
공개 저장소 밖의 허용된 비공개 폴더를 입력·출력 경로로 사용한다.

```bash
python -m pip install -r requirements-regional.txt
python scripts/prepare_regional_card.py --input /PRIVATE/card_provider.zip --output /PRIVATE/card_prepared
python scripts/evaluate_regional_temperature.py --card /PRIVATE/card_prepared/regional_card_daily.csv --chuncheon /PRIVATE/chuncheon_asos.csv --gangnam /PRIVATE/gangnam_aws.csv --calendar /PRIVATE/calendar.csv --output /PRIVATE/regional_results
python -m unittest discover -s tests -p 'test_regional_temperature.py' -v
```

새 출력 폴더를 사용한다. 입력 SHA256, 실행 코드 SHA256, 버전, 선택값, 날짜 품질, 학습·평가 기온 범위를 기록한다. predictions.csv는 재계산 가능한 예측 결과, metrics.csv는 성능, validation_grid.csv는 선택 근거, coverage/fold_coverage.csv는 표본 범위, support.csv는 기온 관측 범위, temperature_response 파일은 조건부 반응이다. 실제 데이터·수치·출력 파일은 공개 GitHub에 올리지 않는다.

## 검토 결과와 남은 한계
실제자료 실행에서 기온·조합항 추가의 개선은 평가기간과 지역에 따라 달랐고 모든 지역·평가기간에서 요일 평균의 WAPE를 낮추지는 못했다. 따라서 복잡한 모델 또는 춘천의 더 큰 기후 피해를 입증했다는 결론을 내리지 않는다. 공통 표본 제한, 62일의 짧은 여름 관측, 2개 지역·지역별 단일 관측소, 강수 등의 미통제, 이미 열람한 자료의 탐색적 재분석 한계를 유지한다. 관측소 자료는 지역 전체 모든 상점의 미시기후를 측정하지 않는다.

팀 리뷰: 선하는 동일 쌍 표본·금액 복원·선택 지표를, 세은은 최고기온 기준과 기존 체감온도 사건의 구분·지역 반응 해석을 검토한다. 기존 회복 계산·지원 기준선은 변경하지 않는다.
