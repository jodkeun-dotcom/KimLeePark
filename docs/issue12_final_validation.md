## 적용 기준과 수정 사항

요일 평균·fixed_pre_event·exclude_missing·effective를 주 분석으로 사용한다. 회복은 95% 이상 달력상 3일 연속이며 공휴일·불완전 날짜에서 연속을 끊는다. 명목 관찰기간 14일·병합 간격 2일을 유지하고 7/21일·간격 3일은 민감도다. HEAT04 실제 3일 창은 원래 상태를 유지하며 짧은 창으로 별도 표시한다.

전체 184일 달력은 #31의 수신 XML 6개·출처·조회일 기록을 사용한다. 이전의 “전체 달력 미확인”, “ALL 계산 연결 미해결”, “기준 최종 합의 대기”는 이번 최종 검증의 미완료 항목이 아니다. 조회일은 2026-10-05이며 정확한 시각은 미확인이다.

계산 코드의 기본 산식을 바꾸지 않았다. 기존 로컬 비교 코드의 입력 버전·달력 상수와 과거 날짜를 파일명에 넣는 방식을 수정했다. 현재 실행의 run_metadata.json과 입력 행 수를 확인하고 입력 SHA-256·실제 달력 출처를 기록한다. 기존 검토 문서를 최종 결과로 자동 덮어쓰지 않는다.

고정 연령 구성, 사건 완전성 90/80%로 조건 완화, 임의 결측 0 채움, k일 내 회복 비율은 새 기본 방법으로 추가하지 않는다. 작은 매출에 합의되지 않은 금액 문턱을 만들지 않는다.

## 방법과 매출 규모 비교

순누적 부족은 Σ(예상−실제), gross는 Σmax(예상−실제,0)이다. 증가한 날과 상쇄한 net은 음수가 가능하다. 부족률의 분모는 같은 표본의 예상합이며 0이면 비율은 공란이다. 연령 비율을 합하거나 금액 단위가 확인되지 않은 값을 원 단위로 단정하지 않는다.

평균/중앙값과 결측 가정을 비교할 때 양쪽 실제·예상이 있는 공통 날짜의 차이와 0가정에서 추가된 날짜의 차이를 분리한다. 부분 날짜 소계를 전체 창의 부족률 또는 지원 입력값으로 치환하지 않는다. 방법 비교 4,419행과 요약 9행을 실제 자료로 재생성하고 일별 요약 5,892행을 독립 재합산해 대조했다.

## 업종 내 고객 연령 비교

기본 비교는 사례 3건 × 업종·연령 491개 그룹, 총 1,473행이다. 고객 연령을 사업주 연령이나 동일 고객의 복귀로 해석하지 않는다.

| 사건 | 비공휴일 관측 불완전 연령 그룹 | paired 날짜 없음 | 공통 날짜 있는 업종 | 공통 날짜 없는 업종 | 비공휴일 전체 공통 업종 |
|---|---:|---:|---:|---:|---:|
| HEAT03 | 228/491 | 106 | 31/85 | 54 | 13 |
| HEAT04 | 214/491 | 80 | 36/85 | 49 | 15 |
| HEAT05 | 209/491 | 79 | 39/85 | 46 | 18 |

paired는 연령마다 날짜가 다를 수 있는 소계다. common은 동일 업종의 모든 입력 연령이 갖춰진 날짜로 맞춘 값이다. 공통 날짜가 없으면 공란, 일부 날짜만 있으면 부분 비교로 표시한다. 예상합·실제합·net·금액 구성비를 함께 제공하며 업종끼리 날짜가 다른 이 표로 업종 순위를 확정하지 않는다.

실제 미관측과 학습 부족은 겹칠 수 있어 단순 합산하지 않는다. lowest_expected_age는 양수 예상합의 업종 내 최소값(동률 포함)이라는 참고 표시다. 비교 가능한 그룹이 하나뿐이면 표시하지 않으며 지원 대상의 제외 기준이 아니다. 입력 연령을 제외하는 고정 구성은 후속 과제로 둔다.

## 공통 전달·단순 감소율 검토

full은 공휴일 포함 전체 창, eligible은 비공휴일 창, paired는 양쪽 값이 있는 소계다. 각 완전성 조건이 다른 값과 공란을 서로 바꾸지 않는다. ALL gross는 동일 연령을 업종 합산한 뒤 양수 처리하며 연령별 gross 합계와 다를 수 있다.

지원 상태 255행과 18개 설정 4,590행은 원래 금액·회복·공란을 보존했다. 주 분석 54행 중 감소율 순위 계산 가능 37행과 Pareto 후보 1행은 서로 다른 대상이다. 회복 판정 불가 197/255(77.3%), 알려진 예상값 비중 사건 기간 63.2%·사건~관찰기간 68.5%를 병기한다. 예상값 비중의 분모에는 계산 가능한 연령별 예상값만 포함되며 춘천 전체 매출 커버리지가 아니다.

#35의 stable 표시는 지원 검토 상태의 안정성을 뜻하며 회복 판정의 불변을 뜻하지 않는다. 민감한 결과는 추가 확인 대상으로 표시하고 단일 설정의 후보를 확정 지원 순위로 사용하지 않는다. #35 자체의 코드·그림 검토는 해당 PR의 기록과 구분한다.

## #12 핵심 결론 3개 및 분석 범위

1. 예상 매출은 과거 같은 요일의 탐색 기준선이다. 제한된 사전 평가와 #31 동일 조건 모델 비교를 근거로 요일 평균을 주 분석으로 채택했으며 폭염 인과적 피해액을 입증하지 않는다.
2. 연령 비교는 동일 날짜·금액·비율·관측 범위를 함께 봐야 한다. 자료 부족이나 작은 예상합으로 큰 비율이 나온 것을 높은 피해 또는 지원 불필요로 단정하지 않는다.
3. 매출 수준 회복과 누적 부족 만회는 다르다. net/gross·기간·완전성을 구별하고 상태별 검토를 중심으로 제시한다. 순위 후보가 1개이고 18개 설정 중 6개에서만 유지되므로 단순 감소율 순위보다 우수하다는 주장은 하지 않는다.

범위는 제공 춘천 개인카드의 2025년 7~12월과 여름 HEAT03·04·05 사례다. 85개 업종 중 주 분석 18개와 보조 탐색을 구분하며 ALL과 연령 상세를 합산하지 않는다. 가을·겨울 모델 평가와 여름 회복 분석을 구분한다. 팀 전체 발표의 결론 선정·실행안은 이 선하 산출물의 결론과 별도 공동 작업이다.

## 재실행·산출물

저장소 루트에서 제공 데이터와 전체 달력으로 만든 동일 기준선 실행 폴더를 사용한다. 원본 입력·실제 업종별 금액·비교 CSV·그림은 공개 저장소에 올리지 않는다.

```text
python scripts/compare_methods.py --source-dir outputs/support_review/baseline --output outputs/issue12_final/methods
python scripts/compare_ages.py --source-dir outputs/support_review/baseline --output outputs/issue12_final/ages
```

필수 입력: daily_predictions.csv, event_shortfall.json(방법 비교), run_metadata.json. 재생성한 기준선도 동일 공휴일·사건·관찰창을 사용해야 한다. 이미 검증한 과거 실행값을 재사용할 때에는 파일 버전·검증 범위를 표시한다.

- 방법: method_comparison_detail.csv, support/summary.csv, support/metadata.json.
- 연령: age_comparison_detail.csv, support/industry_summary.csv, support/age_view.csv, support/stats.json, support/metadata.json.
- 전달: 기존 #32의 sales_handoff.csv와 진단표, #31의 상태·감소율 교차표.
- 공유: 실제 값은 팀 내부 자료와 같은 입력에서 재생성한다. 공개 PR에는 코드와 집계·해석 문서만 포함한다.

## 직접 검증의 범위

앞서 원본 카드·사건·관찰창과 전체 달력으로 예상 매출 198,364행부터 금액·회복 각 1,728행, 지원 상태 255행 및 설정별 4,590행을 재계산해 공유 ZIP과 일치시켰다. 로컬 입력과 조은 기록의 바이트 해시 차이는 줄바꿈이고 내용은 동일하다.

이번에는 동일 검증 기준선으로 방법 4,419행·연령 1,473행을 재생성해 기존 상세표와 모든 열·값이 일치함을 확인했다. 날짜 분할·기준선·매출 전달 검사 24개와 공통 회복 연결 검사 9개, 총 33개가 일반 실행과 python -O에서 각각 통과했다. 실제 재실행 코드가 요약 대조·표본 일치·연령 합계·구성비를 오류 발생 방식으로 검사하므로 최적화 실행에서도 필요한 검증은 유지한다. AI 독립 재학습, 전체 45개 설정의 새 기준선 재실행, #35 그림 재생성은 이번 범위가 아니다. 작성자의 전체 테스트 수를 선하가 전부 실행한 것으로 바꾸어 기록하지 않는다.
