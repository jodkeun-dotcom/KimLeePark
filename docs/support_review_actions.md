# 상태별 지원 검토와 분석 기준

관련 #13, #12, #11, PR #31. 2026-10-05 조은의 실행 요청과 사용자가 전달한 선하·세은의 잠정 동의·보완 의견을 반영했다. 세은의 민감도 파일 대조 결과와 남은 확정 절차는 [공동 검토 기록](team_criteria_review_1005.md)에 구분했다. 실제 지원 대상·금액 승인이나 최종 기준 확정을 뜻하지 않는다.

## 적용한 기준

- 주 분석은 **요일 평균 기준모델**이다. AI 1종은 동일 조건의 비교 결과로 보존한다. 현재 자료의 예측 비교에서 요일 평균 오차가 작았다는 근거이며, 가을·겨울 예측 성능으로 여름 폭염의 인과적 피해 추정 정확성을 입증하지 않는다.
- **예상 매출의 95% 이상을 3일 연속 유지**하는 회복 정의를 주 분석에 쓴다. 공휴일·불완전 날짜는 연속을 끊는다. 관측이 없는 날을 0으로 채우지 않는다. 이 기준은 분석상 정의이며 보편적으로 검증된 최적 기준이라고 주장하지 않는다.
- 지원 검토는 **비공휴일 전체의 순누적 부족률**을 중심으로 순부족 금액·양의 일별 부족분 합계와 함께 읽는다. full/eligible/paired의 기간·분모·공란을 유지한다.
- 평균/중앙값 × 90/95/100% × 2/3/4일의 **18개 설정**을 유지한다. 후보를 늘리기 위해 주 분석 조건을 사후 완화하지 않는다. 설정 빈도는 확률이나 신뢰도가 아니다.

## 모든 업종을 남기는 검토표

기존 잠정 Pareto 등급은 비교 가능한 회복 확인 대상 안에서 유지한다. 별도 `support_review_PROVISIONAL.csv`에는 **ALL 255개 사건×업종 조합을 모두** 남긴다. 주 분석과 보조 업종은 scope로 구분하고 서로 다른 사건의 행을 한 순위로 합치지 않는다.

아래는 순서 없는 범주이며 예산 배분 1·2·3순위가 아니다. 회복 상태·금액·기존 순위 칸을 덮어쓰지 않는다.

| 범주 | 분류 조건 | 제안 조치 |
|---|---|---|
| 매출 자료·지표 부족 | 비공휴일 창 불완전 또는 net/gross/순부족률 중 계산 불가 지표 존재 | 누락 날짜·연령, 예상 합 0 등 계산 불가 원인을 확인하고 재평가 |
| 순부족 있음·회복 판단 자료 부족 | 비공휴일 지표 완전·순부족 양수, 회복 상태 insufficient_data | 확인된 추정 부족을 보존하고 회복 관찰 자료 보완 |
| 순부족 있음·회복 미확인 | 비공휴일 지표 완전·순부족 양수, 회복 상태 censored | 현장 상황·관찰기간 확인 및 단기 지원 필요성 검토 |
| 순부족 있음·회복 확인 | 비공휴일 지표 완전·순부족 양수, 회복 상태 recovered | 매출 흐름 회복 후 남은 누적 부담에 대한 지원 필요성 검토 |
| 순부족 있음·사건 감소 기준 미충족 | 비공휴일 지표 완전·순부족 양수, 회복 상태 no_decline | 사건·관찰기간의 차이와 계절·업종 등 다른 요인 점검 |
| 양의 순부족 없음·상태 점검 | 비공휴일 지표 완전·순부족 0 이하 | 회복 상태·일시적 부족·이후 매출 흐름 모니터링 |

금액 지표가 불완전한 경우에는 먼저 판단 불가로 남기고 회복 상태도 별도 열에서 보여 준다. 순부족률의 분모가 0이면 이를 0%로 바꾸지 않는다. 반대로 회복 판정만 불가능하고 비공휴일 금액은 완전한 경우에는 확인된 양의 순부족을 지우지 않는다.

`no_decline`은 사건 평균 실제/예상 비율이 기준 이상이라는 뜻이다. 회복 확인이나 피해 없음을 뜻하지 않는다. 순부족 0 이하도 기간 중 초과 매출로 상쇄된 결과일 수 있어 양의 일별 부족분 합계와 미회복 상태를 함께 남긴다. 이 범주를 자동 지원 제외로 사용하지 않는다.

## 시점·지속기간·확인 지표

검토표는 사건 시작~유효 관찰 종료까지의 정보를 사용하는 **사후 분석**이다. `assessment_as_of=window_end`를 표시한다. 이를 당시 실시간으로 지원 대상을 예측한 성과로 설명하지 않는다.

각 행에는 `suggested_action`, `suggested_start_condition`, `duration_and_reassessment`, `monitoring_metrics`, `support_review_caution`을 붙인다. 현장 확인·자료 확보·관찰창 종료까지의 부족 확인 등을 검토 시작 조건으로 제안한다. 지원 지속기간은 이 자료만으로 산정하지 않고 추가 관측 확보 시 재평가하도록 기록한다. 지원 효과·필요 예산·금액은 추정하지 않는다.

회복 첫날과 3일 연속 확인 시점은 구분한다. 사건마다 관찰 종료가 달라 `observation_start/end`, `observation_days`, `recovery_observed_days`, `observation_holiday_days`, `observation_nonholiday_unavailable_days`를 함께 보여 준다. 공휴일과 비공휴일의 관측 불가 날짜를 구분하며 회복 미확인에 임의의 14일 등을 넣지 않는다. 짧은 관찰 종료와 실제 장기 회복 지연을 같은 것으로 취급하지 않는다.

현재 주 분석 순위 후보가 1개이고 18개 설정 중 6개에서 유지되는 한계는 그대로다. 범주를 추가한 것은 순위 가능한 업종 수를 늘린 것이 아니다. 미회복·자료 부족도 후속 검토에서 빠지지 않도록 지원 검토의 범위를 명시한 것이다.

## 파일과 재현

[통합 실행](analysis_1007.md)의 priority 단계 또는 기존 `python -m scripts.rank_support` 명령이 아래 파일을 함께 만든다. 실제 CSV·그림은 outputs 안에 두고 공개 GitHub에 올리지 않는다.

- `support_priority_PROVISIONAL.csv`: 기존 잠정 등급, 금액·회복 및 18개 설정 요약. 관찰기간 설명 열을 추가했으며 기존 계산값은 유지한다.
- `support_review_PROVISIONAL.csv`: 모든 기본 설정 행과 순서 없는 범주·제안 조치. 기존 지표·순위도 보존한다.
- `support_review_summary.csv`: 사건·scope·범주별 **사건×업종 행 수**. 서로 다른 사건의 같은 업종을 독립 업종으로 중복 계산해 규모를 설명하지 않는다.
- `support_review_sensitivity.csv`: 18개 설정별 범주. 빈도를 지원 효과 확률로 해석하지 않는다.
- `support_review_overview.png`: 주 분석의 사건별 범주 분포. 범례 순서는 지원 순서가 아니다.
- `priority_rules.json`: 분류 조건·조치와 기존 Pareto 규칙을 기록한다.

추가 출력은 `decline_rank_vs_state.csv`(계산 가능한 모든 감소율의 순위와 상태), `decline_state_crosstab.csv`(사건·지역·scope·비교군별 건수), `decline_state_comparison.png`, `all_completeness_detail.csv`(날짜별/기간별 완전성), `comparison_coverage.csv`(판정 불가 비율과 알려진 예상값 비중)다. 상세 CSV와 그림은 팀 내부용이다.

`decline_rank_all_available`는 0·음수를 포함한 모든 유한 감소율의 순위다. `decline_only_rank`는 기존 Pareto 후보만 비교하므로 의미가 다르다. 동률은 최소 순위, 상위 3위 구간은 동률을 모두 포함하는 설명용 구간이다. 순위 우수성이나 정책 지원 순서를 평가한 지표가 아니다.

`calendar_recovery_start_positions=max(observation_days-consecutive_days+1,0)`은 달력상 가능한 시작 위치 수다. 실제 유효 연속 구간의 수가 아니며 공휴일·결측은 별도로 봐야 한다. `observation_window_constraint`와 `censored_short_window`는 짧은 관찰창을 설명하고 원래 회복 상태를 변경하지 않는다. HEAT04의 3일 창에도 첫날부터 3일 모두 충족하는 경우는 회복으로 남는다.

ALL 판정 불가는 197/255(77.3%)다. 판정 가능 행이 차지하는 **알려진** 연령별 예상값 합의 비중은 사건 기간 63.2%, 사건~유효 관찰기간 68.5%다. 분모는 실제값의 관측 여부와 무관하게 계산 가능한 연령별 예상값을 합한 것이고, 예상값이 없는 셀은 알 수 없으므로 별도 셀 커버리지를 제공한다. 춘천 전체 매출 커버리지가 아니다. 기간 구분은 사건 전체 완전 59행, 비공휴일 창 완전 46행, 공휴일 포함 전체 창 완전 33행으로 다르다.

주 분석 54행 중 감소율 순위는 37행에서 계산되며 기존 Pareto 후보는 1행이다. 사건별 감소율 상위 3위인 9행 중 양의 순부족 없음 3, 매출 지표 부족 2, 양의 순부족·사건 감소 기준 미충족 1, 양의 순부족·회복 확인 1, 양의 순부족·회복 미확인 2행이다. 이는 감소율만으로는 기간 전체의 부족·관찰 제약을 설명하기 어렵다는 비교이며 방법의 우수성 검증이 아니다.

남은 공동 검토는 이번 수정본 확인, #33 새 head `933dd3a` 재리뷰, 관찰기간·병합 간격·회복일 요약 범위의 최종 동의다. #33 수정 코드 업로드는 작업 종료 전 확인했다. 선하의 이전 입력·계산 대조는 사용자에게 전달된 완료 보고로 기록하고, 이번 수정본의 새 비교표 확인은 별도로 남긴다. #12/#13 완료와 구분한다.

## 검증

현재 전체 로컬 테스트 118개가 통과했다. 기존 상태 분류 검사 8개의 최적화 실행 기록에 더해, 이번 비교·완전성 검사 7개도 일반 실행과 `python -O`에서 통과했다. 자료 부족·0·회복 미확인·no_decline 구분, 입력 지표 보존, 비교 대상 집합·동률, 짧은 관찰창, 날짜와 기간 완전성, 실제값 결측이 있어도 알려진 예상값을 분모에 포함하는지를 확인했다.

전체 달력으로 실제 6단계를 재실행해 기준선 198,364행·회복 1,728행·우선순위 255행·민감도 4,590행·모델 성능표 2,074행의 기존 계산값이 유지됐다. #32와의 255개 ALL 조합 비교도 통과했다. 새 검토표 255행에서 원래 지표·순위가 그대로 보존됐고, 설정별 범주 4,590행이 생성됐다. 관찰일·유효 비율 관측일·공휴일·비공휴일 관측 불가 일수는 #32의 일별 곡선에서 별도로 집계해 일치했다.

주 분석 54개 사건×업종 행은 매출 자료·지표 부족 22, 순부족 양수·회복 미확인 2, 순부족 양수·회복 확인 1, 순부족 양수·사건 감소 기준 미충족 7, 양의 순부족 없음 22로 분류됐다. 회복 판단 자료 부족 범주는 이 기본 설정에서는 0행이다. 이 건수는 지원 순위·지원액 또는 독립적인 54개 업종 수가 아니다. 실제 개별 업종 수치는 비공개 공유본에 보관한다.
