# 선하 공통 기준선·고정 예측 검증 초안

관련: #9. 상태: Draft, 팀 검토 전. 기준모델 검증·예상값·부족분의 탐색 계산을 재현합니다.
확정된 폭염 피해액·회복 지표·지원 순위가 아닙니다. #9 전체 완료로 처리하지 않습니다.

## 실행

Python 3, pandas, numpy가 필요합니다.

```text
python scripts/prepare_sales_baseline.py --daily processed/data1/daily.csv --output outputs/sunha_baseline
```

입력 컬럼: date, region, industry, age, amount. 춘천 개인카드의 날짜×지역×업종×연령 일별 집계입니다.
금액 단위는 원자료 그대로 사용합니다. 입력 날짜 중복·결측, 유한하지 않은 금액은 검사에서 중단합니다.
실제 원본·정제자료와 산출 보고서·JSON은 로컬에 보관하며 공개 저장소에 커밋하지 않습니다.

## 잠정 설계

- 전체 85개 업종 유지. 외식·식품·방문형 여가 18개를 주 분석 후보, 나머지를 보조 탐색으로 구분합니다. 분류는 효과 판정이 아닙니다.
- 사건은 PR #24 docs/weather.md에서 옮긴 날짜입니다. 실제 사건 CSV와 대조 전이며 코드의 사건 목록은 잠정 고정값입니다.
- 같은 지역×업종×연령의 이전 비사건일 같은 요일 평균이 기준선 후보입니다. 중앙값은 민감도 비교용입니다.
- 사건 시작 전 모델 고정. 전체 관측 최소 7일·같은 요일 최소 2회는 탐색용 조건입니다.
- 공휴일은 PR #26 목록의 8/15만 잠정 제외합니다. 전체 캘린더 검증이나 공휴일 예측 모델은 없습니다.
- 사건+종료 후 14일 길이에 맞는 사전 검증을 수행하되, 다른 사건일 제외 후 남은 부분만의 점수입니다. 전체 길이의 검증 성공으로 간주하지 않습니다.
- HEAT03은 짧은 사전자료 탐색 사례. HEAT04는 다음 사건 전 8/28까지와 원래 9/8까지 창을 구분합니다. 관찰기간 확정은 팀 합의가 필요합니다.
- 이전 사건의 회복일은 아직 학습에서 제외하지 않았습니다. 14일 모두 제외하면 현재 자료에 학습 가능한 날짜가 없는 문제가 있습니다.
- 행이 없는 날짜를 매출 0으로 채우지 않습니다. partial은 관측 소계이며 full은 전체 기간 계산 가능한 때만 채웁니다.

## 산출물 정의

JSON에 model_id, 사건·기간·업종·연령 키, 학습·관측·예측일 수, complete_window, status를 포함합니다.
gross_shortfall은 max(예상−실제,0)의 합, net_shortfall은 초과 매출을 차감한 합입니다.
decline_rate_event는 사건 발생 기간 전체가 계산 가능할 때만 산출하며 관찰기간의 순부족률과 다릅니다.
평균/중앙값에서 부호가 바뀌거나 순부족률 차이가 큰 사례를 별도 표시합니다. 10%p는 검토용 조건이며 신뢰구간이 아닙니다.
현재 JSON은 내부 검토 형식입니다. PR #28의 최종 결합 형식과 호환 확인 완료가 아니며, 세은의 회복 결과도 아직 연결하지 않습니다.
